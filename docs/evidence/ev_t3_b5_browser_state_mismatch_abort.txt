Live-browser evidence for B5 (state mismatch), real Chromium via Playwright.

1. Genuine login+consent completed for user 'ana'; the browser's own
   sessionStorage held the state it generated at step 1 (redacted).
2. Intercepted the server's real redirect to /client/callback before the
   client processed it. Its state (redacted) was the CORRECT one for this
   browser session: real_state == "2nDKbQ...<redacted>".
3. Replaced only the `state` query parameter with an attacker-forged value
   and navigated the SAME browser (same sessionStorage) to that tampered URL
   -- this simulates a replayed/leaked authorization response. The
   authorization code itself was never exchanged (the guard aborts first)
   and is redacted below regardless.

  "state inválido (posible CSRF). Flujo abortado."
